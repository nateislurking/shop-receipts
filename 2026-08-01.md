> **Why bugs keep appearing in "copied known-good code":** because we didn't copy a product, we carried one across an OS boundary — and every single bug today lives exactly *on* that boundary, not in the product. Look at the three: the exec bit is a concept that **doesn't exist on Windows** (`.exe` files just run — there's no permission bit to forget). The install-root bug exists because a Windows app is a flat folder while a Mac app is a bundle with the executable and resources in *sibling* directories. And the scraper FP wasn't ported code at all — it was **brand-new darwin-only security logic** (the POSIX path recognition) taking its first live traffic. Meanwhile, notice what *hasn't* had a single bug: the engine conversation, activation, the gas gauge, the setup flow, the world-tree writes, STT, the board tools — all the actual product logic, which really is the same code that's had a month of Windows dogfooding. Zero logic bugs, three seam bugs. That's not sloppiness — that's the textbook failure distribution of a port, and it's precisely why the smoke-test gate existed before any customer touched it.
>
> **Why the rest of the surface probably isn't equally mined:** because the app doesn't have a thousand Mac-specific codepaths — it has about four chokepoints everything flows through, and startup is where *all* of them live. [...] Startup was the minefield because startup *is* the platform layer.
